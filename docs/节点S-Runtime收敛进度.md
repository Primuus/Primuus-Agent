# 节点 S：Runtime 工程收敛进度

## S1：项目检查记录一致性

2026-09-30 对 `745057c` 的修复继续收敛。发现编辑后项目检查通过、最终答复复用检查结果时，重新加载只读取最终答复之后的检查事件，导致检查记录丢失。在旧代码副本中复现：会话正常结束，检查执行两条，加载前 `checks` 为两条，加载后为零条。

本节点将项目检查命令集、最近完整检查和补丁 SHA-256 纳入会话状态。开始、逐命令结果、完整批次分别写入事件，最终答复无需重复执行相同检查即可恢复记录。失败后再次修复只展示最近批次；新任务、命令集变更和恢复快照清空旧检查。`checks_current` 只说明检查是否对应当前补丁，检查成败仍由退出码判断。续跑最终答复时重新验证工作区，防止外部改动后直接沿用成功终态。检查命令若改变补丁，该次验证不通过；不匹配当前补丁的结果不会用于写入成功记忆。

## S4：上下文与收尾预算修复

### S4.1：控制上下文输入

同时发现 OpenAI 兼容适配层丢弃了服务返回的 `reasoning_content`。[DeepSeek 多轮工具调用协议](https://api-docs.deepseek.com/guides/thinking_mode/)要求将该字段回传。本次将其纳入响应契约、会话事件和消息重建，压缩时保留近期调用的完整推理字段，使上下文预算能计入这部分内容；不把推理内容当作任务完成确认。

针对 S3 保存的两份 Trace 做上下文重放，压缩后的请求消息分别为 12,790 与 13,319 字符；工具调用与返回配对完整，检查命令和当前任务保留，重载后的上下文与检查记录一致，原始工具事件内容不变。另用一个较长推理与工具输出场景确认，近期消息数量不会阻止压缩，最新调用组的推理字段保持完整。验证使用内联脚本，没有新增工程依赖或保留测试文件。

本部分尚未进行真实模型复测，收尾预算控制仍需继续实现；以上只验证上下文与记录行为，不代表正常收尾瓶颈已经跨越。

### S4.2：请求前分配预算并保留收尾额度

Runtime 在每次请求前根据消息大小和最近实际输入用量估算成本，并留出下一次最终答复的输入与输出额度。预算使用到三分之一时即提示完成定位后编辑，替代此前的 60% 提示。接近 Token 或轮数上限时，先压缩较早的消息；只有当前补丁检查通过、存在对应补丁摘要且计划无待办项时，才将下一次请求切为不提供工具的最终答复。模型仍需核对原始要求并给出答复，最终检查照常确认；检查失败或未检查的任务不会据此自动标记完成。

OpenAI 兼容和 Anthropic 两个适配层均接收实际的单次输出限制，修复原先 OpenAI 兼容入口未传递 `--max-output-tokens` 的问题。输出截断明确作为服务失败，保留接口返回的已知输入输出用量，并在重载后继续计入预算；未知用量仍不伪造为已知。输入估算包含余量，但不是服务端精确计数，不能保证严格的计费上限。

另在补丁恢复为空时清除旧的项目检查并写入事件，避免使用旧成功记录进入收尾模式。对应事件在重载时同样清除检查。

两条真实 Git/Docker 受控路径验证通过：正确补丁在预留额度中得到模型最终答复后正常完成，错误补丁保留失败检查并以预算终止，没有伪造完成；两种模型适配器的请求载荷均传入输出上限，最终答复请求不携带工具。截断用量重载后仍正确计入预算。结果见 [controlled-report.json](../experiments/2026-10-05-runtime-fix/controlled-report.json)。验证使用内联脚本，临时 Git 与容器工作区均已清理。

收尾预算实现已完成，下一步仅复测 S3 的两个任务，保持原有步数、总 Token 预算、源码快照、检查与镜像，采用本次新的上下文和单次输出设置。不扩大到完整测试集或记忆对照。

### S4.4：限制首次编辑前的探索额度

对于允许写入且配置了项目检查的仓库任务，首次编辑前的探索额度设为总 Token 预算的三分之一，默认 40,000 Token。达到额度且尚无当前任务的补丁检查摘要时，模型请求只提供 `write_file`、`edit_file`，并说明编辑后自动运行项目检查。产生补丁和检查摘要后恢复通常工具集，以便处理失败反馈、完成验证与收尾。只读模式、未配置项目检查或没有 Token 预算的会话不启用该限制。
