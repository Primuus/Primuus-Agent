# 节点 M 实施记录

节点 M 在现有普通仓库会话上增加跨任务记忆和隔离的并行任务。每个小目标验证后单独提交，节点完成时汇总可重复实验与边界。

| 小目标 | 内容 | 状态 |
|---|---|---|
| M1 | 仓库级记忆存储：项目知识、失败和有效修复；来源、适用范围、修订和停用 | 已完成 |
| M2 | 从会话结果形成有证据的记忆；新会话按关闭、摘要、检索模式选择上下文并写入 Trace | 已完成 |
| M3 | 固定任务、模型和预算，比较三种记忆模式的跨任务结果，保留可复现实验入口 | 待实施 |
| M4 | 多任务在各自的 Git 副本和容器运行；独立审阅结果，在另一副本上按顺序整合补丁并报告冲突 | 待实施 |

记忆属于仓库外的会话状态，不写回目标仓库。并行任务先独立完成，再整合到新的副本；原仓库始终由用户自行审阅后决定是否应用。

## M1 验证

- 使用两个临时 Git 仓库操作同一个 SQLite 记忆库：新增、列出、修订、查看版本、停用均成功，另一仓库看不到前者记录。
- 每条手工记录保留来源引用和当前提交，适用路径不允许越出仓库；数据库文件仅对当前用户开放。临时仓库和数据库在验证后清理。

## M2 验证

- 在临时仓库先存项目知识，再运行含失败命令、代码修改和通过项目检查的会话：任务相关知识进入模型上下文；Trace 自动保存失败与修复两类记录，修复记录包含改动路径和补丁摘要。
- 创建第二个会话检索同一仓库的修复记录，重新加载事件后选择的记忆 ID 仍可还原。会话和数据库均在临时目录中清理。
