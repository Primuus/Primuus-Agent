# 任务推进与压缩续接

## 本次目标

上一轮 intword 与 boltons 跨文件真实任务均未产生补丁。先修正调查过程中的状态延续，再只运行 intword 一次；只有它通过，才运行跨文件任务一次。失败时停止扩大验证，检查失败证据。

## 已实现的修改

1. 压缩掉完整旧轮次时，单独保存最近被移除轮次的普通说明或推理末尾，最多 2,000 字符，明确标为未验证的工作笔记。它用于延续假设和下一动作，不进入最终报告的事实摘要。
2. 最多保留两个未在当前消息中出现的源码快照，总正文不超过 4,800 字符。优先选择正在处理的计划项所列文件；未列计划时按已观察到的读取次数排序。超过容量的输出仍可按 Trace 调用编号读取，不伪造摘要源码。
3. 新需求、补丁变化或回滚会清除旧工作记录。源码只取当前补丁产生之后的观察，避免拿旧代码继续编辑。被保留的工具轮次仍使用原始完整 reasoning_content。
4. 工作记录进入 context_compacted 日志，重启后可以重建；旧日志没有该字段时仍按原流程重建。没有新增摘要模型调用或永久验证脚本。
5. 多项任务按一项需求的定位、最小修改、检查、下一项执行。上下文展示计划中正在处理的需求及下一动作，不要求先调查完所有文件才编辑。
6. 重复读取提醒比较最近轮次的实际源码行，可以识别穿插其他读取后的重复，以及已被先前范围或整文件覆盖的读取。遇到写入或 Shell 调用停止回溯；同一补丁、同一文件只提醒一次，工具仍可正常调用。

这是有界的状态保留机制，不等同于语义摘要。工作笔记可能只覆盖推导的末尾，也可能包含尚未成立的假设；是否解决任务由真实补丁与独立验证判断。

## 定向验证

使用上一轮两题的真实 Trace 检查：工作笔记和目标源码在压缩后保留、日志重建一致、旧日志兼容、保留轮次的推理原样传递、最终报告不注入假设、补丁变化与新任务清除旧记录。另用已有跨文件读取序列确认范围重叠能够触发一次提醒。

证据：[focused-continuity.json](../experiments/2026-10-07-task-continuity/focused-continuity.json)。全部通过，尚不能据此判断真实任务通过。

## 真实验证约束

- 沿用上一轮固定任务源码树、Docker 镜像、DeepSeek 模型、80 步与 120,000 Token 预算，24,000 字符上下文、保留 8 条消息、工具预览 4,000 字符。
- intword 只运行一次。通过条件：任务完成、有效目标源码补丁、当前补丁检查通过、独立行为验证通过、状态重建一致。
- intword 通过后跨文件只运行一次；未通过则不运行跨文件，不把未执行样本算失败。
- 独立验证内容不提供给模型；密钥只在宿主内存中使用。临时驱动、任务副本、会话工作区和容器用完清除，原始证据放在 experiments/。
- 即使两题通过，也只说明这个局部瓶颈得到改善，节点 S 的整体回归验收仍需另行确认。
