# 节点 K：受控故障注入与恢复验证

运行日期：2026-09-27（UTC）。[原始对照汇总](../../../experiments/2026-09-27-recovery-controlled/comparison-20260927T134208.json)保留每次运行的配置、结果与完整 Trace。

## 对照条件

- 任务：新增的 `task_011`（跨模块分页搜索）和 `task_012`（配置驱动 CSV 导出），每题运行一对基础版与恢复版。每个任务的初始版本均未通过独立 Verifier，临时参考修复均通过。
- 模型：同一个确定性故障注入后端 `controlled-fault-injection-v1`。每次运行的首次模型调用都抛出一次可重试的临时服务错误；下一次调用返回预设的三文件修复动作。这检验恢复链路，**不是 DeepSeek 或其他真实模型的能力测试**。
- 两版使用相同任务内容、模型行为、独立 Verifier、Docker 镜像和每题 5 步、600 秒任务、30 秒工具、60 秒验证器预算。差别仅为恢复开关；每题各运行一次。
- 成功由隔离容器中的独立 Verifier 判定。Agent 容器不接触 Verifier 文件。

## 结果

| 指标 | 基础版 | 恢复版 |
|---|---:|---:|
| 通过任务 | 0/2 | 2/2 |
| 有失败记录的运行最终成功率 | 0/2 | 2/2 |
| 平均模型步数 | 0 | 1 |
| 平均工具调用 | 0 | 3 |
| 平均 Token | 未知 | 未知 |
| 平均耗时 | 0.248 秒 | 1.257 秒 |
| 人工介入 | 0 | 0 |

两版均记录到两次 `model_service` 失败。基础版以 `model_error` 结束；恢复版各进行一次模型重试，再通过三个跨文件写入和 Verifier。失败请求的 Token 用量不可得，所以会话总量记为 `null`；恢复版成功响应中填入的合成用量不当作完整用量。耗时仅反映本机这次运行。每题一次、故障和修复动作预设，结果不能估计真实模型成功率或恢复收益。

每次运行的 `run_id`、任务摘要和相应 Trace 均在[对照汇总](../../../experiments/2026-09-27-recovery-controlled/comparison-20260927T134208.json)中。

## 其他场景

- 使用普通 Git 仓库的隔离会话验证了：首次修改后暂停，重新载入会话，测试命令失败后回退操作前快照，相同测试命令再次发出时被拦截，随后跨文件修改并通过项目检查。最终 6 个模型步骤，原仓库未变。工作区与临时脚本在验证后删除。
- 用旧版真实模型保存的 10 条动作轨迹重放最初 10 个任务，独立 Verifier **10/10 通过**。这验证 Runner 回归，不构成新的模型采样。
- 模型服务永久错误、最终验证失败后的有限再修复和重复动作上限通过一次性进程内场景验证；未留下临时测试文件。

真实 DeepSeek 的成对、重复运行尚未进行：当前执行环境没有提供运行时模型密钥。需要以 `python3 -m coding_agent compare tasks --repeats N` 运行，并继续扩充更接近日常工程规模的仓库任务，才能判断策略的实际收益与代价。
