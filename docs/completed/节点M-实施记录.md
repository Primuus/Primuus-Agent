# 节点 M 实施记录

节点 M 在现有普通仓库会话上增加跨任务记忆和隔离的并行任务。每个小目标验证后单独提交，节点完成时汇总可重复实验与边界。

| 小目标 | 内容 | 状态 |
|---|---|---|
| M1 | 仓库级记忆存储：项目知识、失败和有效修复；来源、适用范围、修订和停用 | 已完成 |
| M2 | 从会话结果形成有证据的记忆；新会话按关闭、摘要、检索模式选择上下文并写入 Trace | 已完成 |
| M3 | 固定任务、模型和预算，比较三种记忆模式的跨任务结果，保留可复现实验入口 | 已完成 |
| M4 | 多任务在各自的 Git 副本和容器运行；独立审阅结果，在另一副本上按顺序整合补丁并报告冲突 | 已完成 |

记忆属于仓库外的会话状态，不写回目标仓库。并行任务先独立完成，再整合到新的副本；原仓库始终由用户自行审阅后决定是否应用。

## M1 验证

- 使用两个临时 Git 仓库操作同一个 SQLite 记忆库：新增、列出、修订、查看版本、停用均成功，另一仓库看不到前者记录。
- 每条手工记录保留来源引用和当前提交，适用路径不允许越出仓库；数据库文件仅对当前用户开放。临时仓库和数据库在验证后清理。

## M2 验证

- 在临时仓库先存项目知识，再运行含失败命令、代码修改和通过项目检查的会话：任务相关知识进入模型上下文；Trace 自动保存失败与修复两类记录，修复记录包含改动路径和补丁摘要。
- 创建第二个会话检索同一仓库的修复记录，重新加载事件后选择的记忆 ID 仍可还原。会话和数据库均在临时目录中清理。

## M3 验证

- `compare-memory` 先冻结记忆数据库，再以相同原仓库提交、任务、检查、模型 ID、配置和预算运行三种模式；比较期间不写入新记忆。每次运行保留独立会话产物和汇总指标。
- 两轮受控跨任务场景得到关闭 0/2、最近摘要 0/2、任务检索 2/2。此结果仅验证选择链路，未使用真实模型；条件与复现脚本见[实验记录](../experiments/2026-09-27-memory-controlled/README.md)。

## M4 验证

- 两个独立文件任务使用同步屏障确认并发运行，各自通过项目检查；两个补丁按清单顺序整合到第三份 Git 副本并通过组合检查，原仓库文件保持原样。
- 两个任务修改同一个文件时，各自检查均通过；整合应用第二份补丁时报告冲突，保留两份 `handoff.json`、Trace 和补丁供审阅，整体状态为失败。
- 通过本地临时模型 HTTP 服务运行 `parallel` CLI，验证清单读取、会话调用、产物和整合报告。临时仓库与脚本均已清理；尚未用真实模型在大型仓库验证并行任务的收益。
- 节点 L/M 结束后复查测试性质脚本：工程内仅有 12 个任务的独立 `verifier.py`，它们是评测数据，继续保留；临时验证脚本没有进入仓库。

节点 M 的四个小目标均已完成。跨任务记忆的受控结果只能证明检索链路有效；真实模型的收益与并行任务的规模化效果仍需按实际仓库、固定预算和重复运行检验。
