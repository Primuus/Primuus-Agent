# 输入成本优化与有限验证

## 目标与范围

在当前 S 阶段 Runtime 上减少模型输入，不进入下一阶段。历史成功记录中，intcomma 输入 57,593 Token，intword 输入 78,656 Token。目标为两道原有任务的输入用量平均下降 20%–30%，同时保持补丁正确、检查通过和会话恢复一致。目标需要实测，不能以请求字符数代替实际 Token。

历史两条记录分别来自不同代码版本和 Recovery 设置，只用于描述性比较，不能作为严格的因果实验。新批次使用同一 Runtime 版本和配置。

## 实现

1. 模型上下文省去工具结果里的重复调用标识、名称、耗时和空字段；Trace 和结果契约保持完整。
2. 从实际工具观察记录生成最多 4,000 字符的历史摘要：源码摘录、成功编辑、执行命令及失败。当前调用组保留完整，不把推理文字记成事实。直接编辑后省去旧源码摘录；恢复工作区后不带入恢复前的操作摘录。
3. 当前任务、计划和最近检查状态独立注入上下文。
4. 最初试验上下文阈值 16,000 字符、近期 6 条消息和输出字段 2,400 字符。验证后未得到稳定的整体成本收益，已恢复原默认值 24,000 / 8 / 4,000。最新一轮分段源码读取先保留原始输出，变成旧消息再缩短；最新完整调用组仍可能超过阈值。

Shell 可执行任意操作，因此历史摘录不保证仍是当前源码；需要精确编辑时读取相应范围。既有预算和阶段约束继续生效。

## 验证批次

| 轮次 | 内容 | 数量 |
| --- | --- | --- |
| 第一轮 | 上下文压缩与事件重建；工具阶段约束；失败项目检查；模拟传输截断的有界重试 | 4 个受控场景，无模型接口 |
| 第二轮 | humanize 的 intcomma 与 intword；packaging 空平台参数；boltons 集合删除与列表边界跨文件任务 | 4 次完整真实 Agent 运行 |
| 第三轮 | intcomma、intword、boltons 跨文件任务各独立再跑一次 | 3 次完整真实 Agent 运行 |

所有真实运行从固定基准源码的干净仓库开始，同一配置，Memory 关闭，Recovery 开启。最多 7 次完整真实任务运行，每次包含若干模型请求。任一真实轮次累计 2 道任务未通过时立即停止该轮，并停止进入后续轮次；未运行任务记为未运行。

第一轮出现关键失败先修复。真实任务失败保留全部证据，先分析；代码改变后作为新批次记录，不能混合旧版本结果冒充同版本验收。

## 通过标准与归档

正常 completed、当前补丁对应的项目检查全部通过、独立隐藏验证通过、从日志重新载入状态一致。只有完整用量的运行参加成本比较；截断导致未知用量记 null，已知用量单列。

仅为本次优化的有限验证，不等同原 S 阶段“全部既有回归任务通过”。报告、Trace、补丁和配置存入 experiments/；临时测试脚本、仓库和工作区验证后删除，生产工程不依赖这些脚本。本文待验证完成后补充结果。

## 针对真实失败的修正

- 最新一轮 `read_file_range` 的输出先完整交给模型，后续再按旧输出上限缩短。仍受 DockerTools 原有输出上限约束。
- 首次编辑阶段持续提供分段读取，支持多个文件；广泛搜索和 Shell 仍关闭，不要求创建无关文件来恢复探索。
- 提示建议通常读取 40–60 行，跨文件任务先定位每个目标；检查通过提示和收尾提示明确要求对照实际编辑，不将既有检查通过当成所有需求完成。
- 工具接受 `/workspace/` 下的绝对路径，并在历史摘要中与相对路径统一。工作区外路径仍不能读取。

只补充 2 个针对性受控场景，均通过：真实 Docker 的两份新源码读取首次完整、后续缩短且日志可重建；首次编辑阶段连续读两个文件后成功编辑，Shell 未执行。工作区内绝对路径可用，工作区外路径被拒绝。临时受控脚本已删除，见 [refined focused-report.json](../experiments/2026-10-05-input-optimization-refined/focused-report.json)。新批次先复核已失败的跨文件任务，再测其他任务。

## 归因与本轮处理

已核对实际模型动作、工具返回、补丁、检查、独立验证、源码读取范围与事件重建。接口适配保留了工具调用组和推理字段；8 次运行均无服务异常，不能将这次跨文件失败归因于传输问题。保留推理字段符合 [DeepSeek 工具调用协议](https://api-docs.deepseek.com/guides/thinking_mode/)。

已确认的问题是：

1. 减短单次输入没有减少探索、重复源码读取和额外复核，总输入未稳定下降。
2. 模型在跨文件任务中仍调用未提供的工具，且在编辑阶段生成无关文件。修正读取流程后仍未做实际修复，说明首次工具限制、模型任务推进与完成判断需要联合重新设计；不能靠继续缩小阈值判断已跨越瓶颈。
3. 当前公开检查不能识别所有原始任务缺陷；Runtime 的 `completed` 只表示会话正常结束并通过配置检查，仍可能不满足任务要求。独立隐藏验证将这两次任务判为未通过。

该跨文件任务在 [9 月 28 日基线](../experiments/2026-09-28-real-baseline/report.json)中也为 0/3，均因 Token 预算终止。这条能力路径尚未收敛，不能用当前三个较短任务通过替代它的验收。

2026-10-05 保留精简工具结果、事实摘要、当前检查状态、最新源码读取和工作区路径修正。撤回收缩默认阈值，恢复既有 24,000 / 8 / 4,000；当时参数回调后没有重新调用模型，不验收为“输入降低 20%–30%”，暂缓第三轮、不进入下一阶段。

下一步应先处理首次编辑阶段的硬性工具限制和依据实际补丁判断完成的流程，再按独立批次测跨文件任务。当前仍缺少同版本全部样本通过的结果，不满足 S 阶段完整验收。

所有临时验证脚本、仓库和工作区已清理。保留报告、配置、Trace、验证结果与补丁数据，见 [refined round-2.json](../experiments/2026-10-05-input-optimization-refined/round-2.json)及各批次 `analysis.json`、`cleanup-report.json`。
